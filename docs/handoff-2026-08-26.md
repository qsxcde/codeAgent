## 三、尚未完成的任务

### 1. session 层重构尚未实施

当前 `src/codeagent/session/` 仍然存在职责过于集中的问题：

- `session.py` 同时负责公开 API、运行流程、事件生命周期、回滚、压缩、持久化、重试、错误处理和同步桥接。
- `session_runtime.py` 同时承担 ReAct/core 运行桥接、审批、steer、事件转换、usage 和副作用追踪。
- `json_file_store.py` 同时负责 JSONL、编解码、锁、索引、usage、fork 和元数据。
- JSONL record 到领域对象的解析逻辑在多个模块重复。
- `SessionStore.append_compaction()` 的协议返回类型与实现行为不一致。
- `continue_recent()` 使用创建时间排序，实际上并不是按最近活动排序。
- confirmation 使用单一 `asyncio.Queue[(request_id, bool)]`，并发或乱序响应存在错配风险。
- `_friendly_error()` 混入 provider/httpx 相关用户提示，边界不够纯粹。
- 文件锁主要是进程内锁，尚未解决跨进程写入保护和显式 fsync 问题。
- `MemoryStore` 与 `JsonFileStore` 的行为存在逐渐漂移的风险。

对应 OpenSpec：

```text
openspec/changes/refactor-session-responsibility-boundaries/
├── proposal.md
├── design.md
├── tasks.md
└── .openspec.yaml
```

该变更的规划产物已经完成，状态为 `3/3 artifacts complete`，但还没有执行 `openspec-apply-change`，因此没有 session 源码迁移。

### 2. “最后一次问答时间戳”尚未实现

目前只完成了设计分析，没有修改源代码，也没有创建独立 OpenSpec 变更。

建议不要复用现有的 `SessionRef.timestamp`，因为它表示 session 创建时间。建议新增：

```python
SessionRef.timestamp          # 创建时间，不变
SessionRef.last_activity_at   # 最近一次成功完成问答的时间
```

旧 session 没有该字段时，读取层回退为 `timestamp`，保证兼容历史 JSONL。

推荐持久化为 JSONL `meta` 记录：

```json
{
  "type": "meta",
  "key": "last_activity_at",
  "value": "2026-08-26T18:30:12.123",
  "timestamp": "2026-08-26T18:30:12.123"
}
```

更新时间的时机应是一次问答成功完成并提交 turn 之后。模型失败、工具失败、取消、压缩、模型切换和标题修改不应更新该字段。

如果该字段用于 `continue_recent()`，应改为按 `(last_activity_at, id)` 排序，而不是继续使用创建时间。

由于该字段会出现在 `SessionRef`、列表排序、UI 和持久化格式中，它属于可观察行为变化，不应直接塞进当前声明 `skip_specs: true` 的纯重构变更。建议另建：

```text
track-session-last-activity
```

或者先把它纳入 session 重构变更，再移除 `skip_specs: true` 并补充 sessions/session-resume 相关规格。

## 四、session 层目标结构

当前提案建议将 session 按职责归并为以下结构：

```text
src/codeagent/session/
├── __init__.py
├── manager.py                         # session 的创建、加载、列表、删除、恢复
├── session.py                         # 对外 facade；保持公开 API 稳定
├── runtime/
│   ├── __init__.py
│   ├── controller.py                  # 一次 run 的生命周期编排
│   ├── confirmation.py               # 工具审批请求与响应匹配
│   ├── event_mapper.py               # core event -> session event
│   └── error_policy.py               # session 级错误归类和映射
├── events/
│   ├── __init__.py
│   └── bus.py                         # 事件发布/订阅
├── persistence/
│   ├── __init__.py
│   ├── protocol.py                    # SessionStore 协议
│   ├── models.py                     # SessionRef、SessionHeader 等
│   ├── records.py                    # JSONL record 类型
│   ├── codec.py                      # record 编解码
│   ├── jsonl_store.py                # JSONL 文件存储
│   ├── memory_store.py               # 内存存储
│   ├── index.py                      # 可重建索引
│   ├── locking.py                    # 锁策略
│   └── commit.py                     # turn 原子提交
├── compaction/
│   ├── __init__.py
│   ├── policy.py                     # 压缩触发策略
│   ├── summarizer.py                 # 摘要生成边界
│   └── details.py                    # 压缩细节和保留策略
└── navigation/
    ├── __init__.py
    └── tree.py                       # session 树和分支导航
```

依赖方向应保持：

```text
app/composition
        ↓
session.manager
        ↓
session.session
   ┌────┼──────────┬────────┐
runtime persistence compaction events
   ↓        ↓          ↓       ↓
 core   core.messages core.messages 纯基础设施
```

其中 `session/` 继续禁止反向导入 `ai`、`tools` 和 `config`。`session.session` 只保留 facade 和生命周期组合，不应重新成为新的 God object。

## 五、建议的接力顺序

然后按 `tasks.md` 分组实施，建议顺序为：

### 第二步：处理 session 时间戳

建议在 session 重构的公开接口稳定之后，单独创建 `track-session-last-activity` 变更。这样可以避免把持久化字段、排序语义和目录重构混在一个难以回滚的变更中。

重点修改位置预计包括：

- `session/persistence/models.py` 或当前 `store_models.py`
- record codec 和 JSONL store
- memory store
- index
- turn commit 流程
- `session/manager.py`
- CLI 和 TUI 的 session 展示
- 对应 session/store/manager 测试

### 第三步：验证与归档

每个阶段先执行 focused tests，再由用户执行全量测试：

```powershell
uv run pytest tests/session -q
uv run pytest tests/tools -q
openspec validate --specs
```

tools 变更在确认全量测试通过后，再使用 `openspec-archive-change` 归档。session 变更和时间戳变更也应在实现、验证完成后分别归档。
