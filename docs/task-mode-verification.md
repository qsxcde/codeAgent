# 任务模式与验证闭环

## 模式

普通输入默认使用 `auto` 模式。它保持现有自然对话体验：可以先读取和搜索项目，只有工作区确实产生文件变更时才进入验证阶段。

- `/ask <消息>`：本条消息只读问答。
- `/plan <消息>`：本条消息只读规划。
- `/code <消息>`：本条消息允许按现有安全策略修改代码。
- `/mode ask|plan|code|auto`：切换后续消息的粘性模式。

问答和规划模式会在工具边界拒绝 `write`、`edit` 以及变更型 shell 命令，并提示切换到 `/code`。权限判断不依赖模型对用户意图的猜测。

## 验证命令

验证命令按以下顺序选择：

1. 当前任务显式指定的命令；
2. 项目配置；
3. 常见项目文件自动探测。

Python 项目可在 `pyproject.toml` 中配置：

```toml
[tool.codeagent]
verify = "uv run pytest -q"
```

未找到安全可执行的命令时，任务结果为“未验证”，系统不会声称修改已完成。

## 验证与修复

任务开始和 Agent 回合结束时会比较工作区快照。只读回合或修改后恢复原状的回合返回 `no_changes`，不会运行测试。检测到变更后，状态依次进入验证；验证失败默认自动修复一次，硬上限为三次。相同命令、退出码、规范化错误尾部和差异指纹重复出现时立即停止。

CLI 和 TUI 会显示验证状态、命令、尝试次数和终态。TUI 在验证/修复期间按 Esc 会取消整个任务，包括模型、工具和验证进程。

本阶段只保留运行时结果，不把完整验证输出和修复轨迹写入会话 JSONL。
