## 全项目代码评审（codeagent）

对 `src/codeagent/` 264 个文件（20,115 行）+ `tests/`（15,364 行）做全面评审，产出
`docs/code-review-2026-08-28.md`。结论：9 严重 / 19 中等 / 12 轻微。

### 方法
- 分层并行静态审查（4 个子 agent 分域）+ 安全分类器**实测**（41 条攻击载荷注入）
- 关键结论逐条回源码复核（不采信 agent 转述）
- 全量测试套件运行取基线

### 核心发现（已实测/复核确认）
- **S1 安全分类器可绕过**：实测 7 条高危载荷判 `allow`——`node -e` 删根目录、
  `base64 -d|bash` 混淆 RCE、`xargs rm -rf`、`tee /etc/passwd`、写 `/etc/cron.d`、
  `docker -v /:/host`、`tar -C /`。根因：DENY 实质靠字面量正则 `\brm\s+.../`，
  解释器白名单只覆盖 bash/sh/zsh/python，无编码混淆检测。
- **S2 敏感文件读取无边界**：`_SECRET_PATH_RE` 只覆盖 `.env`/`.codeagent`，
  实测 `read` 读取 `~/.ssh/id_rsa`、`~/.aws/credentials`、`.git-credentials` 全部 allow。
- **S3/S4 持久化**：`locking.py` 仅 `threading.RLock`（无 OS 级锁）；`commit_turn` 用
  整文件 `write_bytes(original)` 回滚，会擦除并发进程写入且非原子。
- **S5 压缩可清空历史**：`session.py:316` 未挡 `cut >= len(history)`，导致 `kept=[]`
  → 重载时回退全量消息 → 摘要与原文「双重生效」。
- **S9 异步任务泄漏**：9 处 fire-and-forget，`view.py` 关闭清单只含 3 个句柄而实际 7 类任务。
- 测试基线 `1022 passed, 3 failed`。失败根因实测：本机 `resolve_bash()` 选中的
  PortableGit 每次调用向 stderr 吐 `/etc/msystem` 噪声且**冷启动 6.5s**，超过测试
  `timeout=5`。暴露真实缺陷：① `resolve_bash()` 不校验 bash 可用性；② `bash -lc`
  登录 shell 的 profile 输出污染 LLM 上下文。

### 质量亮点（可作重构范式）

## 分层架构专项分析（同日追加）

在评审结论「依赖方向零违规」基础上深挖一层，写了 `scripts/layer_scan.py`
（AST 扫描跨层 import + 各层引用的第三方包，可重复执行）。
**静态 import 方向确实 100% 合规**（`tests/test_decoupling.py` +
`tests/contracts/test_session_boundaries.py` 共 170 项全绿，1.69s），
但以下 4 类耦合**绕过了守卫**，需修正此前「零违规」的表述：

1. **session 耦合 httpx（语义违规）**：`session/runtime/error_policy.py:57,120`
   延迟 `import httpx`，按 `HTTPStatusError/TimeoutException/ConnectError` 分类错误。
   违规点：session 不该知道 ai 层用什么 HTTP 客户端。守卫只匹配 `codeagent.*` 前缀，
   第三方库耦合完全不可见 —— 这是守卫最大的盲区。
2. **app 绕过 tools 层直接执行进程**：`app/task_verification.py:137`（subprocess.run
   git status）、`:313`（asyncio.create_subprocess_exec 跑验证命令）、
   `app/skill_packages.py:343,363`（git clone）、`app/tui/benchmark.py:127`。
   tools 层已有 `tools/execution/process.py`+`shell.py` 统一封装与
   `security/classifier.py`+`bash_rules.py` 安全分类，app 层这条路径**两者都不经过**
   （无安全分类、无统一超时/截断/输出配额）。
3. **core / ai 类型重复 4 组**：`Message`/`ChatMessage`、`ToolCall`（core 用
   `args: dict`，ai 用 `arguments: str`）、`ModelResponse`/`ChatResponse`、
   `StreamEvent`/`StreamEvent`。转换责任压在 `app/composition/model_factory.py`（432 行）。
   core/ports.py 的 docstring 自认「core 自有类型」，属有意设计，但改一处要同步四处。
4. **配置体系分裂**：`app/config.py` 的 `Settings` 用 `env_file=~/.codeagent/.env`；
   ai 层 7 个 provider 各自 `BaseSettings` 只配 `env_prefix`、`无 env_file`，
   即只认进程环境变量、不知道 `~/.codeagent/.env` 存在，靠组合根中转
   （`model_factory.py:349` 读 `Settings().llm_provider`）。与 AGENTS.md
   「凭据仅存 ~/.codeagent/.env」存在语义张力。

### 分层可复用的事实
- 各层规模：app 9530 / session 4657 / tools 3143 / core 2319 / ai 1633 行
- core 引用的 11 个顶层包**全是标准库**（真正做到了零外部依赖）
- ai、tools 均不反向依赖 core/session（真单向，靠 app 组合根装配）
- 守卫规则比 AGENTS.md 更严：还禁止 ai/tools 反向依赖 core、禁止 app/tui 依赖
  ai/tools/config、textual 只允许出现在 `textual_backend.py`
- 显式例外：`app/tui/*` 允许 import `core.events`（7 处）与 `session.navigation.tree`，
  规则里对 app/tui 的禁用列表只有 ai/tools/config，不含 core/session
