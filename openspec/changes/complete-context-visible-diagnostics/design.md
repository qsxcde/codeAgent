## Context

当前预算快照、preflight 结果、自动压缩事件和工具结果治理元数据已经分别存在于 core、session 和 TUI 运行态中，但展示层仍需从多个字段拼接信息。V4-16 的缺口是跨层诊断契约和用户入口，而不是重新计算预算或改变压缩策略。详见 proposal.md 和本变更的 delta specs。

## Goals / Non-Goals

**Goals:**

- 建立一个与 provider、session 存储和终端渲染解耦的诊断数据模型。
- 在每次相关运行期状态更新后，维护可供 CLI/TUI 读取的最新诊断快照。
- 通过 CLI `--context` 和 TUI `/context` 提供完整、只读、可解释的诊断视图。
- 保持不确定窗口、估算值、失败和收尾不确定等状态的诚实表达。
- 用单元、契约和 CLI/TUI 集成测试覆盖诊断数据和展示边界。

**Non-Goals:**

- 不改变上下文预算公式、preflight 阈值或自动压缩候选策略。
- 不把诊断快照写入 JSONL，不修改现有消息、usage、父级链或压缩持久化格式。
- 不在状态栏中塞入全部明细；状态栏只保留紧凑摘要。
- 不引入费用估算、远程监控或跨进程诊断历史。

## Decisions

### 统一数据模型，分离采集与渲染

在 `core/context` 定义只包含领域数据和状态枚举的上下文诊断模型，覆盖预算组成、窗口来源、preflight、压缩和工具结果治理。session 运行态负责保存最近快照及有限的最近一次结果，事件适配层负责把已有结构化事件合并到快照中；CLI 和 TUI 只读取该模型并各自渲染。

这样可以避免 CLI/TUI 分别从 session 私有字段推断状态，也避免 core 直接依赖终端、provider 或持久化实现。相较于让展示层解析事件文本，结构化模型能够稳定表达未知、失败和取消状态。

### 采用显式 CLI `--context` 入口

在现有 headless CLI 增加 `--context` 选项：它可以与 `--session` 或 `--continue` 一起查看已恢复会话，也可以在一次 `--prompt` 运行后输出该轮形成的诊断；查看动作本身不启动新的模型请求。默认 headless 回复继续保留现有用量尾行，避免每次对话都输出长篇预算明细。

相较于无条件把完整诊断附加到每次回复，显式选项不会破坏现有脚本输出；相较于增加独立的诊断进程，它可以复用已装配的 session 和同一份运行态快照。

### 采用 TUI `/context` 入口，状态栏只做摘要

在 TUI 命令注册表中增加 `/context`，在聊天区或现有只读信息面板中渲染结构化诊断。面板按照“当前预算 → 组成 → preflight → 最近压缩 → 工具结果治理”的顺序展示；无数据、未知和失败状态使用稳定的空态或标签。状态栏继续显示占用摘要和阶段状态，不与完整面板共享终端宽度布局逻辑。

这能保持 V4-19 的固定槽位约束，同时为用户提供可主动查看的详细信息。面板打开、刷新和关闭均为只读操作。

### 运行期只保留诊断，不扩展持久化格式

预算和 preflight 快照在每次请求前更新；压缩开始、结束以及工具结果治理完成时更新对应诊断；模型切换和会话恢复后清除无法沿用的瞬时字段并重新标记待计算状态。诊断信息只保存在当前 session 的运行态，恢复会话时仅使用已有持久化事实重新构建可用快照，不回放或伪造历史诊断。

最近一次压缩保留消息标识或稳定范围描述，而不是复制完整消息内容；工具结果只保存原始量、展示量、动作、原因和结构化事实完整性，避免诊断快照无界增长或泄漏工具正文。

### 共享测试夹具，分别验证数据和展示

为预算完整、窗口未知、压缩成功/跳过/失败、工具结果治理和失败请求建立可复用的诊断夹具。core/session 层验证快照合并和只读语义；CLI/TUI 层验证字段分组、未知状态和无副作用入口；不依赖真实 provider、网络或外部进程。

## Risks / Trade-offs

- [运行态字段来源分散] → 以结构化事件和统一快照为唯一展示输入，禁止 CLI/TUI 重新推断预算状态。
- [诊断字段过多导致终端输出难读] → CLI 使用分组和显式 `--context`，TUI 使用可滚动面板，状态栏维持摘要。
- [压缩范围标识在恢复或分叉后失效] → 使用稳定消息标识/逻辑范围并在无法映射时显示未知，不展示错误的精确范围。
- [provider 未提供窗口或 usage] → 保留 `uncertain`/`fallback` 来源和明确空态，禁止计算并显示伪精确比例。
- [新增诊断路径意外产生副作用] → 对 CLI/TUI 查看入口增加无模型、无工具、无写入契约测试，并检查会话快照前后相等。
- [旧调用方没有诊断能力] → 诊断接口采用可选读取能力；旧 session 仍可运行，展示层对缺失能力显示明确未提供状态。

## Migration Plan

1. 先加入 core 诊断模型和 session 运行态适配，接入现有预算、preflight、压缩和工具治理事件。
2. 增加 CLI `--context` 和 TUI `/context` 只读入口，保留现有 `/status`、状态栏和 headless 用量输出。
3. 运行窄测试、分层测试、完整测试、Ruff、OpenSpec 校验和构建检查，并将 V4-16 状态更新为完成。
4. 如需回滚，移除新入口和诊断适配即可；不需要迁移或清理 JSONL 数据，因为本变更不改变持久化格式。
