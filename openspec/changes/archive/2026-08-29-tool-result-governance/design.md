## Context

当前工具执行链路已经在部分工具中产生截断、退出码和耗时信息，但这些字段没有以统一的结果对象贯穿工具适配、core 归一化、生命周期事件、tool message、JSONL 持久化和 TUI。部分路径还会先把进程输出完整读入内存，随后才进行展示层截断。相关约束和外部行为见 proposal.md 以及本变更的 `tools`、`core`、`context-budget`、`sessions`、`tui` delta spec。

本设计保持现有工具调用协议、工具名称与输入参数不变，并兼容旧的 `ToolResult` 调用方和旧 JSONL 会话。核心层不能依赖具体工具、模型 provider、文件系统或 TUI；预算和持久化能力通过接口或已有组装层注入。

## Goals / Non-Goals

**Goals:**

- 建立一份可在工具执行、模型上下文、事件、会话和 TUI 之间复用的结构化结果事实。
- 在原始输出采集阶段和下一次模型请求前分别施加资源上限与上下文预算上限。
- 保留不同工具对头部、尾部、路径、范围、stderr、退出码和变更摘要的语义，同时让完整性和截断原因可判断。
- 让旧调用方和旧会话继续工作；缺失元数据时表达为未知，而不是推断为完整。
- 让大结果在默认路径中保持有界内存和有界 JSONL 记录，并可由 TUI 稳定展示。

**Non-Goals:**

- 本变更不设计新的工具协议、模型 provider 接口、权限模型或工具调用调度策略。
- 不默认建立完整原始输出仓库，也不承诺在工具层已经丢弃数据后恢复全部内容。
- 不用 LLM 总结替代确定性的截断、统计和元数据；智能摘要可作为后续独立变更。
- 不在 core 中加入具体进程、MCP、文件系统或终端 UI 实现。

## Decisions

### 1. 以结构化结果元数据作为唯一权威事实

在 `core` 的结果契约中增加与现有 `ToolResult` 兼容的输出元数据模型（可采用嵌套 metadata/envelope，或由现有字段组成的明确值对象）。至少包含：状态与语义成功、完整性、总字节数/行数、当前展示字节数/行数、截断原因、路径或范围、退出码、耗时、stderr 摘要、变更摘要和可选的不透明 artifact 引用。模型可见文本单独作为有界内容字段。

结果对象必须区分：工具执行失败、工具执行成功但输出不完整、输出完整但语义结果为空、元数据未知。字段缺失不能被归一化为“完整”或“成功”。现有扁平字段和构造方式保留兼容读写，新的生产路径统一填充结构化事实。

选择结构化事实而不是继续扫描文本标记，是因为文本可能来自文件内容、用户输入或模型输出，容易误报；结构化字段也能让事件、会话和 TUI 共享同一语义。旧文本标记仅在没有结构化元数据的旧适配器/旧会话中作为兼容回退，并将结果标为低置信度或未知。

### 2. 采用两级限制和三种视图

结果治理拆成两个独立阶段：

1. 工具级硬上限在执行适配器/输出采集处生效，限制读取字节、行数、记录数、单项大小和可保留的 stderr，避免先把无限输出加载到内存。
2. 请求级预算在构造下一次模型请求前生效，根据 provider 可用上下文、系统提示、工具定义、历史消息、输出预留和 headroom 计算本轮可用空间，再对每个结果做确定性的裁剪或短摘要。

两级限制产出的三个视图分别是：

- 模型视图：有界文本，包含必要的结果状态、统计、截断原因和继续操作提示，但不塞入仅供 UI 使用的内部对象。
- 事件/会话视图：结构化元数据和有界模型文本，用于恢复、诊断和状态同步。
- TUI 视图：从结构化元数据、可选 artifact 引用和有界预览渲染范围、分页、导出能力，不通过再次执行工具或调用模型补数据。

选择确定性裁剪而不是默认 LLM 摘要，是因为裁剪必须可测试、可复现、低延迟且不引入额外 token 消耗。预算不足时按工具策略保留最有价值部分并明确缺失信息；不得为了满足预算静默删除截断事实。

### 3. 由工具策略决定保留形态，由公共 governor 执行限制

在 `tools/shared` 增加公共治理组件和策略值对象。governor 接收原始结果事实、工具类别、硬上限和请求预算，返回有界内容及结构化元数据；它不依赖 TUI 或 provider。策略通过配置/注册表按工具类别注入，而不是在各个工具中复制 byte/line 截断逻辑。

默认策略如下：

| 工具类别 | 默认保留信息 |
| --- | --- |
| bash/process | 受限 stdout，stderr 尾部摘要，退出码、运行时长和失败状态；无法保留全部输出时标记不可恢复 |
| read | 路径、起止范围/偏移、内容预览、总行数或字节数以及继续读取提示 |
| grep/find/ls | 匹配/条目计数、受限结果列表、搜索参数和继续范围；不能把列表裁剪误报为无匹配 |
| write/edit | 路径、操作结果、变更摘要和必要的 diff/计数；不重复保留大文件全文 |
| MCP | 文本内容按相同限制处理；图片、音频、二进制或未知块显式记录为 unsupported/reference，而不是静默丢弃 |
| skill | 指令正文和资源预览按硬上限处理，保留 skill 标识与不可完整加载诊断 |

若某工具有继续读取、分页或 artifact 能力，策略输出 opaque `artifact_ref`/continuation 信息；引用必须不泄露凭据和不绕过现有文件权限。没有可恢复来源时，元数据明确表示不可恢复，TUI 不提供虚假的完整导出。

### 4. 在现有执行链路上补齐元数据传递

保持层次方向如下：

```text
工具/进程/MCP采集
  -> tools/shared governor
  -> AgentToolAdapter 与 core normalize_tool_result
  -> ToolResult / lifecycle event / tool message
  -> session JSONL metadata
  -> TUI projection
```

`normalize_tool_result` 必须保留已存在的结构化字段和新元数据，而不是重新只读取少数字段后丢弃其余信息。`AgentToolAdapter`、并发 batch 的工具结束事件、事件映射、turn 的 tool message 构造必须使用同一结果对象或等价的不可变快照，并保留工具调用 ID、批次顺序和结果身份。

core 只负责契约、归一化和传播；工具层负责采集与策略；app composition 负责注入 governor、预算提供器和可选 artifact 端口。这样可以用 fake governor/预算替身做离线测试，且不让 core 直接依赖配置、网络或持久化。

### 5. 以可选 JSON 字段持久化，旧会话缺失信息即未知

在 tool message 的 JSONL 编解码中增加版本兼容的可选 `output`/metadata 字段，只写有限大小的结构化元数据、有限模型文本和不透明引用；不写未受控的完整原始 stdout、stderr 或二进制。字段编码应稳定、可 JSON 序列化，并对未知未来字段容忍读取。

旧记录没有该字段时保持原有内容和工具调用字段，恢复投影把完整性设为 unknown/legacy，而不是默认 complete。新记录在执行失败、取消或事务回滚时不伪造成功的输出元数据。若输出已经被硬上限丢弃，记录截断原因、统计和不可恢复状态，而不是生成看似完整的 artifact。

### 6. TUI 只消费结构化元数据，兼容解析隔离

`OutputBuffer`/结果块的内部记录改为保存结构化 snapshot 与有界预览。摘要显示路径、范围、状态、退出码、耗时、变更摘要、总量和展示量；分页/展开只在已有 preview 或 artifact 可读时执行，不触发模型请求或工具重跑。`can_export` 等能力由 completeness、artifact 可用性和安全边界决定。

为兼容旧会话或第三方旧适配器，保留一个隔离的 legacy marker parser；只有结构化字段完全缺失时才使用，并把冲突、无法确定的情况呈现为 unknown/diagnostic。结构化字段与文本标记冲突时，结构化字段优先。

### 7. 用分层离线测试锁定边界

测试按职责放置：

- `tools/shared` 单测覆盖空输出、精确边界、字节/行双限制、头尾策略、stderr、非文本块和超大流式输入。
- core contract/normalization 测试覆盖字段不丢失、失败/取消/未知状态、并发结果身份与顺序。
- context-budget 测试覆盖模型切换、历史与工具定义占用、预算不足、多结果和确定性裁剪。
- session 集成测试覆盖新旧 JSONL、回滚/取消、敏感字段不落盘和元数据恢复。
- TUI 测试覆盖结构化优先、legacy 回退、分页/导出能力和不可恢复截断。

测试使用 fake provider、fake artifact、`tmp_path` 和有限内存的流式替身，不连接真实网络、MCP 或用户目录。

## Risks / Trade-offs

- **结果文本变化可能影响模型行为** → 保持原有工具调用和核心成功语义；模型文本加入稳定的状态/统计格式，并用既有场景和契约测试锁定兼容边界。
- **两级限制导致重复裁剪或预算抖动** → 明确记录每一级的截断原因和原始/展示统计；预算计算使用单次请求快照和固定 headroom，避免累计扣减。
- **默认不保留完整原始输出降低恢复能力** → 优先使用工具已有的安全 artifact/继续读取能力；没有来源时显式显示不可恢复，不承诺隐式恢复。
- **旧适配器只返回字符串** → 兼容归一化路径保留字符串结果，并把完整性标为 legacy/unknown；迁移测试确保不因缺字段伪造成功。
- **非文本 MCP 内容无法放入模型文本** → 显式记录类型、大小和引用/不支持原因；避免静默丢失造成模型误判。
- **敏感信息可能通过统计或引用泄露** → 元数据不复制原始内容，路径/引用沿用现有脱敏和权限校验，导出继续受现有安全边界约束。

## Migration Plan

1. 先引入兼容的结果元数据契约、治理策略和归一化测试，保持旧字段与旧 JSONL 可读。
2. 接入进程、原子工具、MCP、skill 和 adapter，补齐硬上限、工具策略及结构化结果。
3. 贯通 core 事件、turn tool message、context budget 和 session 编解码；对旧记录采用 unknown/legacy 投影。
4. 切换 TUI 到结构化 snapshot，保留隔离的 legacy fallback，并运行分层测试、完整测试和 OpenSpec 校验。
5. 若发现兼容性问题，可关闭新 governor 注入点并继续使用旧字符串归一化；JSONL 新字段为可选，旧版本仍可读取新记录中已知字段之外的内容。

## Open Questions

- 首个实现版本使用哪一组默认字节、行数和请求 headroom 数值，可在任务实现时依据现有配置和回归基线确定，不改变上述字段、阶段和工具策略。
- 是否为特定 MCP artifact 类型提供持久化后端，可在已有安全 artifact 能力确认后单独落地；本变更只要求显式记录引用、不支持或不可恢复状态。
