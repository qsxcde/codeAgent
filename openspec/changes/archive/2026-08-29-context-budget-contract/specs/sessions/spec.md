## ADDED Requirements

### Requirement: 会话上下文预算状态与用量隔离

会话 SHALL 分别维护最近一次模型请求的预算估算、最近一次 provider 实际 usage 和已经成功提交轮次的累计 usage。预算估算和本轮实际 usage 可以作为运行期诊断状态暴露,但不得替代已有消息历史,也不得未经成功提交直接写入累计用量。

#### Scenario: 请求开始记录预算估算

- **WHEN** 会话开始一次模型请求
- **THEN** 会话记录包含模型窗口、输入组成、输出预留和余量的预算估算,并将其标记为请求前 estimate

#### Scenario: 响应后记录实际用量

- **WHEN** provider 返回本轮实际 usage
- **THEN** 会话更新最近一次实际 usage,同时保留请求前 estimate,二者不会互相覆盖

#### Scenario: 成功提交后聚合用量

- **WHEN** 一轮运行成功完成且消息与 usage 一起提交
- **THEN** 该轮实际 usage 才进入累计 usage,累计值不包含本地估算值

#### Scenario: 失败轮次隔离

- **WHEN** 一轮运行失败、取消或提交失败
- **THEN** 该轮不会改变已提交累计 usage,其预算估算和实际 usage 只能作为本轮诊断状态保留

### Requirement: 模型窗口切换更新预算

会话运行时切换 provider、model 或 reasoning effort 后,下一次请求 SHALL 立即使用新模型选择结果中的上下文窗口和输出限制计算预算;切换不得改写既有消息、父级链、压缩记录或历史 usage。

#### Scenario: 切换到更小窗口模型

- **WHEN** 用户将当前会话切换到上下文窗口更小的模型并继续对话
- **THEN** 新请求预算使用更小窗口重新计算,既有会话历史和压缩记录保持不变

#### Scenario: 切换到更大窗口模型

- **WHEN** 用户切换到上下文窗口更大的模型并继续对话
- **THEN** 新请求预算使用新窗口,不会把之前模型的估算或实际 usage 伪装成新模型能力

#### Scenario: 切换后恢复

- **WHEN** 进程重启后恢复一个发生过模型切换的会话
- **THEN** 会话按最近模型配置恢复预算元数据,历史 usage 仍按原已提交记录累计,不重复计算
