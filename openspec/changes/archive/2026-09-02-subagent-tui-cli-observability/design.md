## Context

当前父级 EventBus 已发布四类有界 Subagent 事件，但 TUI 的模型归约器只处理普通消息和工具生命周期事件；由于专用事件携带 child session/run 身份，直接送入现有 runtime 归约还会被过期 run 校验忽略。headless 的事件循环同样只聚合正文和 token 用量。既有 TUI 已有按块渲染、点击展开、固定状态栏槽位、帧调度和长会话布局缓存能力，V5-07 应复用这些边界而不引入第二套会话或运行时。

## Goals / Non-Goals

**Goals:**

- 将 V5-06 的专用事件投影为可定位、可更新且不泄漏子 transcript 的 TUI 委派块。
- 让 parent run 校验、终态幂等、乱序/迟到事件和多委派隔离在展示层成立。
- 在固定状态栏中增加有限委派聚合，并在 headless 一次性/交互模式提供稳定状态行。
- 以离线单元、契约和渲染性能测试固定可观察行为。

**Non-Goals:**

- 不改变子 Agent 的调度、预算、权限、取消或结果契约；这些由前置 V5-01～V5-06 负责。
- 不把子 transcript 持久化或加入普通会话历史；父会话有界运行记录属于 V5-08。
- 不实现并行 Subagent、交互式子 Agent 控制台或新的 `/subagents` 命令。

## Decisions

### 1. 使用专用投影，不复用 ToolCallBlock

新增展示层的委派状态投影和独立渲染块。`ToolCallBlock` 继续只表达父级工具调用；委派块表达子 Agent 的独立生命周期，因此不会把 child 事件伪装成普通工具进度，也不会把委派结果当作普通工具输出。投影按 `delegation_id` 保存状态，终态后拒绝状态回退，并保留有限的终态去重记录。

替代方案：把委派事件转换成 `TOOL_*` 事件并复用工具块。该方案会丢失父子 run 语义，容易让 child 文本进入工具输出，也无法诚实显示确认等待和清理不确定，因此不采用。

### 2. 专用事件先于父 runtime 归约处理

TUI 模型在处理专用事件时，先校验 `parent_run_id` 是否匹配当前父 runtime，再更新委派投影和状态栏聚合；这些事件不调用会改变父 phase、父时钟或父 session/run 的通用 runtime transition。普通事件仍沿现有 `RuntimeReducer` 路径处理，保持兼容。

替代方案：放宽 `RuntimeReducer` 对 child session/run 的关联校验。该方案会使 child 身份有机会覆盖父级运行状态，扩大过期事件的影响面，因此不采用。

### 3. 事件只携带有限展示元数据

在父级 Subagent 事件的 metadata 中补充有界的 `profile` 和单行 `task_label`（或等价安全标签），由事件构造处从请求中生成并截断；进度 payload 继续只接受阶段、工具摘要、耗时和短诊断。终态只读取 `SubagentResult.to_dict()` 中的摘要、状态、失败和统计字段，不在 TUI/CLI 侧解析或复制完整 prompt/context。

替代方案：让 TUI 通过父级 `TOOL_CALL` 与后续终态按时序猜测委派对应关系。该方案在多个委派、队列等待和乱序事件下不可靠，也会把模型输入文本留在长期视图中，因此不采用。

### 4. TUI 和 headless 共用投影规则，输出各自适配

将状态规范化、终态判定、序列/归属校验和有界文本处理放入无终端依赖的展示层辅助逻辑；TUI 使用该投影渲染块和聚合，headless 使用同一投影生成稳定行。headless 只在状态发生可见变化时输出，并对同一委派最多输出一次终态，避免重复事件造成脚本噪声。

替代方案：分别在 TUI 和 headless 中解析事件。重复逻辑会导致状态标签、错误码和安全边界漂移，因此不采用。

### 5. 采用小而固定的缓存边界

每个委派的任务标签、摘要、诊断和进度细节均设固定字符/行数上限；活动委派与终态去重集合使用固定容量，终态块只保留紧凑投影。块通过现有 transcript 的局部失效和可见区布局路径更新，不保存 child transcript，也不为每个进度事件追加新块。

替代方案：保留所有 child 事件以支持事后完整回放。该方案违背本阶段的隐私、内存和长会话目标，完整运行记录留给后续显式能力，因此不采用。

## Risks / Trade-offs

- [事件缺少可用 task label] → 使用固定的“子 Agent 委派”标签并保留 delegation_id；事件构造处补充有界 profile/标签，不能从无界 payload 猜测。
- [子事件与父级普通事件交错] → 只接受匹配 `parent_run_id` 的专用事件；专用事件不推进父 runtime phase，终态和序列检查保持幂等。
- [状态栏空间不足] → 委派聚合只占运行区的短字段，复用现有 cell 宽度截断和固定三栏降级规则。
- [高频进度导致 UI 刷新过多] → 进度只更新一个投影并沿现有事件缓冲/帧调度合并，测试记录帧、缓存和控制延迟指标。
- [CLI 状态行改变既有脚本输出] → 仅在实际收到 Subagent 事件时增加带固定前缀的行，普通单 Agent 输出保持原顺序和内容。

## Migration Plan

1. 先补充专用事件中有限的展示元数据和展示层投影/格式化测试。
2. 接入 TUI 模型、委派块、状态栏聚合和点击/布局失效路径，再接入 headless 两种循环。
3. 运行相关 TUI/CLI、Subagent 契约和性能测试；通过后更新 v0.5 记录和主规格。
4. 回滚时移除展示层消费路径即可；V5-06 的事件发布保持向后兼容，未装配展示消费者的普通运行不受影响。
