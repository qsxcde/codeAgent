## Context

现有会话恢复由持久化层读取最新压缩状态，再由 `AgentSession` 保存摘要、摘要 entry 和保留消息。运行时会把摘要转换为一次模型可见的虚拟消息，并在提交阶段过滤该虚拟消息；JSONL 后端则继续保留被摘要的物理消息。TUI 还需要把同一逻辑上下文投影为 transcript，并对大历史使用后台恢复。

目前的测试分散在 Store、压缩、SessionManager 和 TUI 模块中，缺少从“成功提交 → 压缩 → 新实例恢复 → 继续/分叉/切换模型”的完整状态流验证。本设计只增加跨模块回归契约和必要的最小修复，不引入新的恢复服务或持久化格式。

## Goals / Non-Goals

**Goals:**

- 用同一组可比较的逻辑上下文快照验证 `MemoryStore` 和 `JsonFileStore` 的恢复语义。
- 明确区分物理 JSONL 历史、恢复后的逻辑上下文和模型请求中的虚拟摘要。
- 覆盖压缩、重启、继续、重复压缩、分叉、模型切换和工具结果 metadata 的组合状态。
- 验证 TUI 对压缩上下文的投影以及异步恢复结果的会话归属保护。
- 通过确定性、离线的 fake provider 和 summarizer 让回归稳定可重复。

**Non-Goals:**

- 不改变 JSONL 版本、entry 类型或已有旧会话读取格式。
- 不删除被压缩的物理消息，不实现历史损坏自动修复或完整原始工具输出仓库。
- 不引入真实 provider、网络、MCP 或 subprocess 作为回归测试依赖。
- 不重新设计压缩策略、预算算法、TUI 组件或 SessionManager 的公共 API；只有测试暴露出的违反既有契约的问题才做最小修复。

## Decisions

### 1. 将逻辑上下文和物理历史分开断言

测试辅助函数分别生成：

- 逻辑快照：`summary`、`summary_entry_id`、保留消息 ID、角色、内容、父级 ID、工具调用 ID 和工具结果 metadata；
- 物理快照：Store 返回的完整消息 ID、压缩 entry 链、模型变更、usage 和 JSONL 行数/内容摘要。

这样可以同时证明“旧消息没有被删除”和“旧消息没有再次进入模型上下文”，避免用 `history` 长度误判压缩行为。模型调用记录另行断言虚拟摘要的数量和位置，确保它只存在于模型视图。

### 2. 使用双后端契约矩阵

恢复、继续、压缩和分叉的共同场景使用参数化后端：内存测试验证快速状态转换，JSONL 测试验证编码、追加写入、重新构造和索引无关的真实恢复。两种后端都必须产出等价的逻辑快照；文件特有的 append-only、流式读取和旧 JSONL 测试保留在 JSONL 专项测试中。

不选择只测试 JSONL，因为会漏掉内存后端在分叉/恢复状态复制上的语义偏差；也不选择只测试 MemoryStore，因为无法发现摘要虚拟消息、metadata 或模型变更的编码回归。

### 3. 每个场景都实际重建对象

测试不会直接修改会话私有字段模拟恢复，而是先通过公开会话运行和 Store 提交状态，再用同一 `session_id` 构造新的 `AgentSession` 或新的 `SessionManager`。继续场景必须检查 fake model 的实际请求消息以及继续后的 Store 内容，证明恢复状态真的被消费。

### 4. 使用确定性摘要和预算替身

摘要器返回包含输入窗口标识和既有摘要的稳定文本，便于断言一次压缩与二次压缩的合并关系。模型配置使用固定的 context window、output reserve、reserve tokens 和 window source；模型切换测试使用两个不同窗口的 fake model，比较恢复前后的预算字段，而不依赖真实 tokenizer 或 provider 返回值。

自动压缩测试在成功提交轮次后重新计算预算，并验证物理历史不会被重复计入；手动压缩测试验证显式压缩路径和恢复路径共享相同的边界语义。

### 5. 将分叉测试拆为两个边界

一个场景从最新 `firstKeptEntryId` 之后的 user 消息分叉，验证子会话携带摘要和保留窗口；另一个场景从压缩边界之前分叉，验证子会话只保留摘要语义而不复制已摘要消息。两个场景都要重新构造子会话并继续一轮，同时检查父会话文件和压缩记录未改变。

### 6. TUI 使用可控的异步恢复替身

TUI 测试复用现有的 fake manager 和 model，分别覆盖摘要/工具 metadata 的同步投影，以及由可控 `to_thread` 替身制造的后台恢复竞态。测试在恢复中切换当前会话，确认旧快照不会替换 transcript、状态栏或输入状态；恢复失败则只验证当前会话收到明确诊断，不要求改变已有错误展示协议。

### 7. 只在回归失败时修复生产代码

先新增回归测试并运行受影响测试集。若失败，按照失败所属边界修复最小生产代码：优先修正持久化编解码、逻辑上下文重建、父级链接或会话归属判断，不通过放宽断言掩盖后端差异。每个修复都需要保留对应的回归测试，并重新运行既有压缩、分叉、预算和 TUI 测试。

## Risks / Trade-offs

- [过度断言摘要文本或虚拟消息文案导致测试脆弱] → 主要断言摘要 entry ID、消息 ID、父级链、摘要出现次数和结构化字段；只对稳定的摘要来源前缀做必要断言。
- [MemoryStore 与 JsonFileStore 的历史表示天然不同] → 共同断言只比较规范化逻辑快照；物理 entry、索引和流式约束保留后端专项断言。
- [异步恢复测试存在时序抖动] → 使用事件、任务和可控线程替身，不使用固定 sleep；每个测试显式等待恢复任务结束或取消。
- [模型预算估算受实现细节影响] → 使用固定模型配置并比较窗口、reserve、输入预算和来源等稳定字段，不断言未经约定的 tokenizer 精确值。
- [工具 metadata 旧格式缺失] → 构造真实旧形状 JSONL，断言 unknown/legacy；不要求旧数据凭空恢复原始 metadata。
- [现有工作区包含其它已完成变更的未归档产物] → 回归只读取这些能力的公开接口和已落地格式，不修改或重新归档无关 OpenSpec 变更。

## Migration Plan

1. 先加入共享快照辅助函数和双后端基础恢复测试，确认未压缩会话的基线。
2. 加入压缩、重复压缩、继续和物理历史保留测试；若失败，实施对应的最小修复。
3. 加入分叉边界、模型切换预算和 tool metadata 恢复测试。
4. 加入 TUI 摘要投影、旧结果状态和异步过期保护测试。
5. 运行受影响窄测、`unit/contract` 分层测试、完整测试、Ruff、`git diff --check`、OpenSpec 校验和构建检查。

本变更不需要数据迁移。若实现修复引入回归，可回退生产代码修复；新增测试和 delta spec 保留，用于重新定位违反的恢复契约。
