## Context

See `proposal.md` for the motivation. 当前 JSONL 与 MemoryStore 已有通用 `set_meta/get_meta`，键为 `name`；索引和列表已能读取该键并优先于首条用户消息派生标题，但 SessionManager 没有公开命名操作，TUI 也没有对应命令。标题派生目前只在读取时归一化自动标题，显式名称缺少统一的长度和单行约束。

## Goals / Non-Goals

**Goals:**

- 为文件和内存存储提供一致的标题归一化、校验和重命名语义。
- 复用 append-only 元数据路径，让重命名不改写消息、压缩记录和 fork 父级链。
- 让 TUI 能设置、查看标题并呈现失败原因。
- 保持既有自动标题、列表、恢复和树形展示的兼容行为。

**Non-Goals:**

- 不引入新的 JSONL entry 类型或修改消息格式。
- 不实现模型生成标题、标题搜索、批量命名或独立标题编辑器。
- 不让标题命名操作隐式切换会话、启动模型或中断当前对话。

## Decisions

### 1. 复用 `name` 元数据而不是修改 header 或消息

重命名通过既有 `set_meta(session_id, "name", value)` 追加一条元数据。JsonFileStore 的索引增量应用和 MemoryStore 的内存元数据都已具备后写覆盖语义，因此重启后读侧可以继续使用最新值；消息 id、压缩切点和 `parentSession` 不发生变化。直接修改 header 会破坏 append-only 约束，向首条消息写入标题会污染模型上下文，均不采用。

### 2. 在共享标题派生函数中做单行有限归一化

标题输入统一折叠 Unicode 空白、去除首尾空白并按现有 20 字符展示上限截断；自动标题和显式标题共用该路径，避免索引命中与回源扫描产生不同结果。SessionManager 在追加前拒绝归一化后为空的标题，避免空标题静默覆盖为不可见值。存储层仍保留通用 `set_meta`，以兼容既有元数据调用方。

### 3. 命令由 TUI 分派、操作由 SessionManager 承担

命令解析器只注册 `/name`，不读取存储；会话命令协作者处理参数、展示当前标题并调用 manager 的重命名端口。Manager 负责确认当前会话/存储存在、归一化和持久化，成功后 TUI 再从会话列表读取实际标题用于反馈。这样 UI 不依赖 JsonFileStore，MemoryStore 和测试 fake 可以复用同一行为契约。

### 4. 错误采用就地反馈且保持无副作用

无当前会话、未装配存储、空白标题和存储失败均转换为命令区信息；不创建会话、不提交消息、不触发模型请求。存储写入沿用现有锁与索引失效处理，失败时由现有异常向上反馈，不新增静默回退。

## Risks / Trade-offs

- [Risk] 20 字符截断可能丢失用户输入尾部 → 反馈实际生效标题，并保持历史消息完整；后续若需要更长展示可单独调整标题契约。
- [Risk] 既有调用方直接 `set_meta` 可能写入不规范值 → 读取侧统一归一化，命名入口严格校验；通用元数据端口不在本变更中扩大校验范围。
- [Risk] 当前会话在运行中被重命名时与消息追加并发 → 元数据与消息均走既有存储锁，命名不改变运行态，列表最终以索引源指纹重建结果为准。

## Migration Plan

无需迁移。旧 JSONL 没有 `name` 时继续按首条用户消息派生；旧文件已有 `name` 时读取时应用相同安全归一化。回滚代码不会删除已追加的 meta entry，旧版本会忽略该通用元数据或继续显示兼容标题。
