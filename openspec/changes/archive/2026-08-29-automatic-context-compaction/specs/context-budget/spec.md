## ADDED Requirements

### Requirement: 自动压缩使用下一次请求预算

自动压缩策略 SHALL 使用代表下一次模型请求的预算快照作为决策输入。该快照 SHALL 基于当前已提交历史、当前摘要、可用工具定义、system prompt、输出预留、安全余量和最终模型窗口重新计算,并分别暴露输入估算、有效输入预算、余量、窗口来源和不确定性。该决策不得依赖会话累计 usage,也不得要求 provider 必须返回本轮实际 input tokens。

#### Scenario: 工具结果影响下一次压缩判断

- **WHEN** 一轮对话产生较大的工具结果并成功提交,系统准备下一次模型请求
- **THEN** 下一次请求预算包含该工具结果的估算,自动压缩策略使用更新后的预算判断,不复用上一模型请求的预算结果

#### Scenario: 缺少实际 usage 时使用本地估算

- **WHEN** provider 没有返回本轮实际 input tokens,但模型窗口和请求组成可用于本地估算
- **THEN** 系统仍生成下一次请求的预算快照并供自动压缩消费,同时保留 estimate 或 uncertain 来源标记

#### Scenario: 模型切换重新计算压缩预算

- **WHEN** 会话切换到上下文窗口或输出限制不同的模型
- **THEN** 下一次请求和自动压缩分别使用新模型元数据重新计算有效输入预算、触发阈值和压缩目标,不得沿用旧模型的预算边界

#### Scenario: 压缩后重新验证预算

- **WHEN** 自动压缩生成摘要和保留消息候选
- **THEN** 系统用同一预算口径重新估算该候选作为下一次请求的输入,并将压缩前后预算与判定结果提供给诊断层
