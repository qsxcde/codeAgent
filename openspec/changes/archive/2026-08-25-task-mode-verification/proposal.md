## Why

当前所有输入都会进入同一个完整的 Agent 会话流程。简单问答、方案讨论和代码修改没有明确的权限边界；如果将“任务级验证闭环”直接套在每一轮对话上，纯问答也会触发测试、差异检查和修复尝试，增加延迟并造成误导。另一方面，代码修改完成后目前缺少一个由实际工作区变更触发的、可观察且不会虚报成功的验证闭环。

需要把用户意图模式与执行能力分开，并以真实的工作区变更作为是否验证的硬条件：问答和规划保持只读，代码模式允许修改；只有确实发生了文件变更，才进入验证与有限修复流程。

## What Changes

- 增加 `ask`、`plan`、`code` 三种会话模式，以及 `auto` 默认策略；支持 `/ask`、`/plan`、`/code` 和 `/mode` 进行单次或粘性模式切换。
- 为模式建立工具/权限边界：问答和规划禁止写入、编辑及其它变更工作区的操作；代码模式沿用现有确认和安全策略。
- 在应用层增加任务监督器，包裹现有 `AgentSession`，维护任务阶段、取消、验证和最终结果；核心 ReAct 循环保持通用，不承载任务策略。
- 在任务开始和结束采集工作区基线，以 Git 差异为首选、工具事件为辅助，只有检测到实际变更时才启动验证。
- 增加验证命令选择与执行：支持显式命令、项目配置和常见项目文件自动探测；返回结构化退出码、状态、耗时和有界输出，并支持超时/取消。
- 验证失败时将命令、退出码、变更文件、差异摘要和截断错误尾部交给修复回合；修复次数有上限，重复失败指纹提前终止，未验证时不得声称完成。
- 将 bash 的退出码和执行状态作为结构化结果向上传播，避免从人类可读输出中解析验证结论。
- 在 CLI 和 TUI 显示模式、任务阶段和验证结果；验证/修复期间阻止重复提交，Esc 可取消整个任务。

本变更不持久化完整的验证日志或任务结果；会话恢复和长期任务历史另行规划。

## Capabilities

### New Capabilities

- `task-mode-verification`: 定义会话模式、权限边界、变更触发的验证、失败修复闭环、任务状态和结果契约。

### Modified Capabilities

- `tui`: 增加模式命令、任务级运行状态、验证进度展示和任务取消行为。
- `tools`: 增加 bash/工具执行结果中的结构化退出码与状态传播，供验证监督器可靠判定。

## Impact

- 主要影响 `src/codeagent/app/` 的命令解析、任务编排、CLI/TUI 集成，以及 `src/codeagent/tools/atomic/bash.py` 和工具结果事件模型。
- `src/codeagent/core/loop.py` 保持通用 ReAct 职责；新增监督器通过现有会话事件和工具接口接入。
- 需要补充模式解析、权限拒绝、无变更不验证、验证成功/失败/超时/取消、重复失败和 TUI/CLI 展示的离线测试。
- 默认行为采用 `auto`：允许只读探索，实际修改后才进入代码验证；用户可用显式模式覆盖该策略。
