## Context

现有 `StatusBar` 已采用会话、运行、上下文三栏和固定宽度预算，能够在阶段、token 数和临时提示变化时保持区域边界稳定。当前 `refresh_runtime()` 没有独立的周期性调用，任务验证事件也没有把验证阶段耗时作为状态栏自己的计时来源，因此无新事件的长时间工具或验证过程可能显示停滞或语义错误的耗时。

本变更只补齐 TUI 状态投影、计时刷新和回归验证。`TuiBackend.set_status()` 继续接收单行 `RichLine`；不修改 Agent 事件协议、会话持久化或工具执行逻辑。

## Goals / Non-Goals

**Goals:**

- 保留现有三栏状态栏布局，确保动态内容只在所属槽位内更新。
- 区分 Agent runtime 阶段耗时与任务验证/修复阶段耗时，并让两者都能在无新事件时受控刷新。
- 任务进入终态后保留最终耗时，停止状态计时调度。
- 用注入时钟和离线后端测试覆盖宽度断点、Unicode、长命令、任务终态和交互不阻塞。
- 让 V4-19 的实现状态可以由稳定、可重复的回归基线证明。

**Non-Goals:**

- 不重新设计或拆分现有状态栏的三栏视觉布局。
- 不增加新的 runtime、task 或工具业务状态。
- 不修改 `core`、`session`、`ai`、`tools`，不改变事件和持久化格式。
- 不把 V4-22 的跨平台性能报告、长会话索引或工具状态治理纳入本变更。

## Decisions

### 1. 将任务计时作为独立的显示状态

在 TUI 模型/状态投影中维护任务阶段开始时间、当前阶段耗时和终态冻结值。收到新的任务阶段时重置阶段开始时间；同一阶段的普通刷新只更新耗时；进入终态时保存最终值并标记计时停止。使用注入时钟保证单元测试不依赖真实时间。

任务事件中的阶段、命令、尝试次数和消息仍作为显示事实来源；不使用上一 Agent runtime 的 `phase_started_at` 推导验证耗时。这样可以修正 Agent 回合结束后才开始验证时，状态栏仍显示旧 runtime 计时的问题。

备选方案是让 `TaskSupervisor` 将每个阶段的绝对时间写入任务事件。该方案会扩大任务层事件契约和测试面，而状态栏只需要显示层的阶段计时，因此本变更优先采用 TUI 状态投影内的注入时钟。

### 2. 增加低频状态刷新而不引入轮询业务

在 `TuiRenderCoordinator` 中增加与活动动画分离的状态计时任务。任务仅在 runtime 或 task 处于活动阶段时运行，以固定的低频间隔刷新 TUI 模型的显示时钟并请求已有帧调度器；不发起模型、工具或会话请求。

状态刷新复用现有渲染合并、generation 和取消机制。输入、滚动、确认或取消事件仍只执行轻量状态操作；退出和终态路径必须取消状态计时任务，避免后台任务持有 TUI 或继续提交状态帧。

备选方案是把耗时更新绑定到每个 Agent 事件。它无法覆盖长时间没有事件的工具/验证阶段，也会使显示准确性依赖事件频率，因此不采用。

### 3. 继续用单行区域级渲染验证布局

不改变 `StatusBar.render(width)` 和 backend 端口。测试通过展开 `RichLine` 后计算终端 cell 位置，验证会话区分隔线和上下文区右边界在运行阶段、任务状态、计时位数、token 数和临时提示变化前后保持一致。

宽度测试覆盖现有布局断点及其相邻值，内容测试覆盖长命令、中文/全角字符、未知上下文占用和所有任务终态。这样可以验证稳定性不只是某个宽度下的字符串快照。

### 4. 分层测试计时语义与交互安全

- 状态栏单元测试验证阶段开始、时间推进、终态冻结和区域锚点。
- TUI 模型/协调器测试验证无新 Agent 事件时状态计时仍触发渲染、输入相关回调不被阻塞、终态后刷新任务停止。
- 保留现有 backend 契约和 `/status` 诊断测试；完整跨平台性能指标留给 V4-22。

## Risks / Trade-offs

- [风险] 周期性状态刷新增加空闲阶段的 UI 调度 → [缓解] 仅在 runtime/task 活动时启动，并在终态、取消和关闭路径立即停止。
- [风险] runtime 与 task 同时活跃时显示语义可能拥挤 → [缓解] 运行区优先显示任务阶段和验证命令，Agent 阶段作为受控次级信息，完整诊断继续通过 `/status` 提供。
- [风险] 注入时钟的刷新边界与真实事件到达时刻存在轻微差异 → [缓解] 以 TUI 收到任务阶段事件作为显示阶段起点，并覆盖单调时钟和终态冻结行为。
- [风险] 极窄终端可能只能显示阶段和部分当前操作 → [缓解] 沿用既有优先级和 cell 宽度截断，禁止状态刷新改变区域边界。

## Migration Plan

1. 增加任务阶段显示计时状态和注入时钟接口。
2. 接入低频、可取消的状态计时刷新，并与现有渲染调度合并。
3. 补充状态栏布局矩阵、任务终态和异步无事件场景的回归测试。
4. 更新 V4-19 文档和必要的主规格同步内容。
5. 运行 TUI 窄测试、分层测试、全量测试、Ruff、OpenSpec 校验和构建检查。

回滚时可移除状态计时任务及任务显示计时字段；现有三栏 `StatusBar` 和 backend 接口不需要回滚迁移。
