## Why

工具执行的底层结果已经携带超时、取消和清理不确定等结构化信息，但 TUI 目前主要在收到最终结果后更新工具块，排队、实际开始、等待确认、进度、取消无结果收尾以及结果截断等状态无法稳定、完整地呈现给用户。并发工具和异常收尾因此容易出现“仍在执行”、通用失败或成功但结果不完整等误导性反馈，影响用户判断 Agent 是否安全地结束以及下一步是否可操作。

## What Changes

- 建立统一的工具生命周期展示契约，明确区分排队、执行中、等待确认、已完成、失败、超时、已取消和清理不确定状态。
- 让工具生命周期事件携带稳定的 `tool_call_id` 和结构化状态，使队列、开始、进度、终态、结果与取消事件可按调用归属归约，不依赖解析人类可读文本。
- 补齐 TUI 工具块对全过程事件的投影，并在取消、拒绝、超时和无结果收尾时更新对应工具块，而不是遗留为 pending/running。
- 将执行结果状态、资源清理状态和输出完整性/截断事实分开展示；保留路径、退出码、耗时、错误、清理诊断和结果范围等已有结构化元数据。
- 修正运行时聚合统计：进度事件不得重复增加 running 数量，超时、取消和清理不确定不得全部折叠为普通失败；状态栏继续保持紧凑，完整详情放在工具块中。
- 增加覆盖正常、并发乱序、确认、失败、超时、取消、清理不确定、重复事件、无结果取消和结果截断的离线回归测试。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `core`: 工具执行生命周期事件需要提供可归属、可区分的排队/开始/进度/终态及取消收尾事实。
- `tools`: 工具执行状态、清理状态和结果完整性需要保持结构化且彼此独立，供展示和测试直接使用。
- `tui`: 工具调用块和运行统计需要完整呈现工具生命周期、终态诊断及结果截断信息，并正确处理乱序、重复和缺失结果事件。

## Impact

- 影响 `src/codeagent/core` 的工具执行事件与状态契约、`src/codeagent/session` 的事件翻译，以及 `src/codeagent/app/tui` 的运行时归约、工具块和状态展示。
- 需要扩展或兼容现有工具状态值（包括当前 `ok` 到用户可见“已完成”的映射），不改变工具执行顺序、并发上限、模型回填顺序或确认安全策略。
- 主要是事件 metadata 和 TUI 展示行为的增强；JSONL 中已有结构化字段应保持可读取，旧事件/旧结果缺少新字段时需有安全兼容默认值。
- 不新增第三方依赖，不重新设计 ReAct 主循环或底部状态栏布局。
