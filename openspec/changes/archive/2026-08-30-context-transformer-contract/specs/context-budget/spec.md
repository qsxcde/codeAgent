## MODIFIED Requirements

### Requirement: 上下文扩展隔离与兼容组合

系统 SHALL 为每次模型请求创建独立的临时消息视图，并先调用旧式 `transform_context`，再调用预算感知的上下文准备扩展；配置了两类扩展时不得绕过任一入口。两类扩展的输入 SHALL 只包含当前请求范围内的消息副本，预算感知扩展 SHALL 只接收中立的消息、工具定义和预算快照。扩展返回值 SHALL 是消息集合且其中每项均为有效消息；非法返回值、扩展异常或超时 SHALL 以结构化上下文准备错误结束当前模型请求，不得静默回退到未变换上下文。转换结果只作用于当前模型请求，不得修改会话持久化历史或组合根中的工具对象。

#### Scenario: 旧扩展与预算扩展按顺序组合

- **WHEN** AgentLoopConfig 同时配置 `transform_context` 和 `context_preparer`
- **THEN** 系统先把旧转换器的结果交给预算扩展，再把预算扩展返回的临时消息交给模型，原始会话消息保持不变

#### Scenario: 扩展只看当前请求的隔离视图

- **WHEN** 上下文扩展读取或修改消息、工具定义或嵌套参数 schema
- **THEN** 扩展只能观察和修改当前请求的副本，持久化历史、真实工具实例及其 schema 保持不变

#### Scenario: 预算扩展接收中立工具视图

- **WHEN** 请求包含内置工具、MCP 工具或其它工具适配器
- **THEN** `ContextPreparationRequest.tools` 只包含名称、描述和参数 schema 等中立定义，扩展不能获得或修改实际工具实例

#### Scenario: 扩展返回非法消息集合

- **WHEN** 任一上下文扩展返回 `None`、不可迭代值或包含非 Message 项的集合
- **THEN** Runtime 发出 `context_preparation_failed` 错误并阻断模型调用，不使用原始上下文作为隐式回退

#### Scenario: 扩展调用超时

- **WHEN** 配置了正的上下文扩展超时且任一扩展在该时限内未完成
- **THEN** Runtime 发出错误码为 `context_transform_timeout` 的上下文准备错误并阻断模型调用；已持久化历史保持不变

#### Scenario: 取消上下文扩展

- **WHEN** Agent 在等待上下文扩展时被取消
- **THEN** 取消异常继续向调用方传播，不被转换成普通准备失败，且不得启动模型请求

### Requirement: 预算快照不改变持久化上下文

系统 SHALL 为预算计算和预算感知的上下文准备生成当前请求使用的临时视图或诊断快照，不得删除、重排或改写会话持久化历史。调用方 SHALL 能在不改变原始消息列表的情况下重新计算同一请求的预算；上下文扩展的失败或超时也不得产生部分持久化修改。

#### Scenario: 预算计算保持历史不变

- **WHEN** 系统为一次请求计算预算或执行预算感知的上下文准备
- **THEN** 会话原始消息、父级关系和压缩记录保持不变，只有本次模型请求使用的临时视图可以变化

#### Scenario: 重复计算可观察一致

- **WHEN** 请求组成和模型窗口没有变化且重复计算预算
- **THEN** 预算组成、估算口径和来源标记保持一致，不会因读取或诊断动作累积额外 token

#### Scenario: 扩展失败保持历史可重试

- **WHEN** 上下文扩展抛出异常、返回非法结果或超时
- **THEN** 本次模型请求失败但原始历史仍可用于下一次请求，且不会残留扩展生成的临时消息
