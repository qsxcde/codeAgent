## Context

当前 `AgentSession`、`SessionManager`、运行控制器和 `JsonFileStore` 同时承担状态编排、事件映射、确认管理、文件读写、索引维护和分叉处理。详见 `proposal.md`；现有 `sessions` 规格中的 JSONL 格式、生命周期、压缩、分叉和用量语义必须保持不变。

## Goals / Non-Goals

**Goals:**

- 让 session 顶层协调、运行时状态、持久化原子提交和文件存储实现分别拥有清晰边界。
- 让异步会话路径通过统一边界调用同步 JSONL 后端，保证事件循环不被文件 I/O、锁和 `fsync` 阻塞。
- 保持已有 JSONL 文件格式、恢复结果、父子链、失败回滚、取消收尾和事件语义。
- 移除已迁移模块的根级兼容门面，并让生产代码和测试只依赖真实职责入口。
- 通过协议类型表达存储、摘要、策略和运行时关闭器的最小能力。

**Non-Goals:**

- 不修改 JSONL 格式、版本号、已有用户数据或会话排序规则。
- 不改变 agent、provider、tool 或 TUI 的业务行为。
- 不引入新的第三方异步文件库或改变持久化介质。
- 不在本变更中处理仍处于进行中的 context-budget 变更。

## Decisions

### 1. 保留同步文件后端，在会话异步层增加统一执行边界

持久化后端继续负责锁、追加、索引和回滚等同步原子操作；异步会话层通过一个集中适配器将“整次提交”放入受控线程执行，而不是把每个文件操作分别包装。这样可以保留当前锁和回滚实现，避免引入新的文件库，同时防止 `commit_turn`、压缩追加和恢复写入直接阻塞事件循环。

适配器需要跟踪正在执行的后台操作。收到取消时，不能简单丢弃 `to_thread` 的外层 Future；必须等待或观察后台原子操作得到确定结果，再报告取消或 cleanup_uncertain，确保读侧不会看到半提交。

备选方案是把所有 JSONL 操作改写为原生异步文件 API。该方案会重复实现现有锁、fsync 和回滚逻辑，迁移风险更高，因此不采用。

### 2. 按“协调 / 状态 / 存储原子操作 / 文件细节”拆分模块

- `session.py` 保留稳定的 `AgentSession` 外观，把运行轮次协调、生命周期收尾、历史提交和压缩触发委托给小模块。
- `runtime/` 将确认队列、事件映射、运行状态、执行与最终化分开；控制器只负责流程协调。
- `persistence/` 将 JSONL 文件访问、批量提交、索引读取、分叉文件构造和兼容适配分开；`JsonFileStore` 只保留公开存储外观。
- `manager.py` 将活动会话注册、当前会话切换和关闭等待分开，管理器不直接承载存储细节。

拆分以现有测试可观察行为为边界，优先移动代码和收紧依赖，不改变公开类的业务语义。

### 3. 用协议替换公共注入点的 Any

在 session 领域定义最小协议，例如会话存储、摘要器、运行时关闭器、上下文变换器和策略接口。构造函数和公开方法使用这些协议；具体的 AI、工具和文件后端仍由 app 组合根注入。这样既满足类型可读性，也避免 session 反向依赖具体实现。

### 4. 一次性移除已迁移的兼容门面

先用全仓库搜索替换生产代码、测试和文档中的旧导入，再删除根级 `bus.py`、`store*.py`、`json_file_store.py`、`tree.py` 和 `session_runtime.py` 等仅负责转发的模块。保留 `codeagent.session` 包的必要稳定导出；只有明确属于迁移兼容层的子模块路径被移除。

备选方案是长期保留转发模块。该方案能降低短期破坏，但会继续隐藏职责边界并允许新代码依赖旧入口，不符合本变更的目标，因此不采用。

### 5. 先建立回归测试，再逐批移动实现

为异步持久化增加事件循环可调度、取消、失败回滚和索引一致性测试；为入口迁移增加真实入口可导入、旧入口不可导入的契约测试。每完成一组模块拆分，先运行对应 session 单元/契约测试，再运行完整离线测试和 OpenSpec 校验。

## Risks / Trade-offs

- [后台线程在取消后仍可能短暂运行] → 以整次原子操作为边界跟踪 Future，取消路径等待确定结果或显式标记 cleanup_uncertain，禁止静默继续下一轮。
- [移除兼容入口会影响外部调用方] → 在变更说明和迁移文档中列出替代导入路径；删除前更新仓库内所有引用，并以契约测试锁定新入口。
- [大规模移动可能改变隐式导出] → 保留必要的包级导出，逐步移动并执行导入收集和全量测试。
- [拆分后模块数量增加] → 每个模块只承载一个高内聚职责，避免用新的“大门面”重新聚合实现细节。

## Migration Plan

1. 先新增协议、异步持久化边界和回归测试，确保现有后端行为不变。
2. 按 runtime、persistence、session facade、manager 的顺序拆分模块并更新导入。
3. 删除已迁移兼容入口，更新文档和测试中的导入路径。
4. 运行窄测试、分层测试、Ruff、`git diff --check`、OpenSpec 校验和完整离线测试。

回滚时恢复兼容入口和旧导入即可；由于 JSONL 格式和数据文件不变，不需要数据回滚。
