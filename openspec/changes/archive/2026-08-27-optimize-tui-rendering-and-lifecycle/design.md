## Context

当前渲染已具备帧调度、可见区 overscan 和按 revision 的布局缓存，但每帧仍检查全部历史 block，流式 assistant 会重解析累计正文，缓存也没有淘汰旧 revision/宽度的路径。会话恢复只按消息数量卸载后台；退出在事件循环中安排异步 runtime close，却不等待完整收尾。详见 [proposal.md](proposal.md) 与本变更的 `specs/tui/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让常见的尾部流式更新只触碰合并后的 delta、变化 block 与可见布局范围。
- 保证布局缓存和 runtime 注册表均有可验证的释放路径。
- 在不改变事件顺序、Markdown 最终结果、滚动语义和会话持久化的前提下改善长会话体验。
- 让退出、取消、热切换和大内容恢复具有明确的异步所有权。

**Non-Goals:**

- 不替换 Textual、不引入数据库、后台 daemon 或跨进程缓存。
- 不重写通用 Markdown parser；只优化当前受控 renderer 的流式输入策略。
- 不实现多轮消息队列；忙碌时保留草稿并反馈，而不是推测应何时自动发送。

## Decisions

### 在展示层聚合可合并事件

新增只属于 TUI 的 pending-delta 缓冲。相邻 `TEXT_DELTA` 与 `THINKING_DELTA` 分别合并，并在下一次允许的渲染帧、结构事件或终态前应用；工具调用、确认、错误、取消、恢复和回合终态立即先刷新缓冲再处理。

选择展示层而不是修改 EventBus：会话记录和其它订阅方仍接收完整事件序列，TUI 只减少重复的视图状态更新。

### 使用有界的 block 布局缓存与高度索引

缓存以 block 身份保存其当前 revision 的布局结果和高度；revision 变化时替换旧结果。Transcript 只保留当前宽度及有限数量的最近宽度变体，并在 block 删除、clear 或全局容量达到上限时淘汰最旧条目。

维护按 block 排序的高度/行范围索引，使用二分定位可见起点。尾部 block 更新只重算该 block 及必要的后缀偏移；展开历史工具块才从其位置更新后缀。选择简单前缀高度索引而非 Fenwick Tree，因为 TUI block 数量和修改模式以追加尾部为主，复杂树结构没有基准证明其必要性。

### 用稳定边界缓存流式 Markdown

完成的 assistant block 保持其渲染缓存。活动 assistant block 将已稳定的完整段落或闭合代码块固化，仅重解析从最后一个安全边界开始的尾部；未闭合结构仍走现有宽容规则，回合终态执行完整校正渲染。

若安全边界不可判定或尾部超过受控阈值，退化为当前纯文本/完整受控渲染路径，优先保证正确性。选择该方法而不是引入通用增量 Markdown parser，以限制语义风险。

### 按恢复成本后台构建

计算历史消息数、可见文本字符数和工具输出字节数的成本估算；任一阈值超出时，在后台构建新的 model/transcript。应用结果前再次检查 current session id；取消或过期结果直接丢弃。

### 显式拥有异步关闭流程

将 TUI 关闭建模为一次幂等 async shutdown：停止输入、取消任务、等待任务完成或超时、取消工具、关闭 runtime、注销 runtime 引用、解除事件订阅，最后退出 backend 并输出完整文档。热切换复用同一关闭协议后再安装新 runtime。

`AgentRuntime` 负责从 registry 注销自身；TUI 只协调何时等待，不直接管理 MCP 或模型实现细节。

### 忙碌提交保留草稿

当输入被运行、恢复或压缩锁定时，不清空 composer，不创建并发任务。控制器更新一条短暂状态/提示，提示用户等待或使用现有取消键位。

## Risks / Trade-offs

- [流式合并错误改变事件可见顺序] → 对结构事件设置强制 flush，并用脚本化交错事件测试顺序。
- [Markdown 安全边界判断漏掉跨段结构] → 终态完整校正、未闭合回退和 Markdown 回归用例覆盖。
- [布局索引与滚动点击映射不一致] → 将行范围索引作为唯一映射来源，覆盖 resize、折叠和跟底测试。
- [异步关闭等待过久] → 设定有限超时并把清理不确定状态显式呈现/记录，仍保证 backend 最终退出。
- [缓存上限造成偶发重渲染] → 缓存淘汰只影响性能，不改变结果；用基准选择默认容量。

## Migration Plan

1. 在性能基线变更完成后，先增加事件顺序、缓存释放、恢复过期和关闭幂等测试。
2. 引入有界缓存与高度索引，保持现有渲染输出快照不变。
3. 引入 TUI delta 聚合和流式 Markdown 稳定边界缓存。
4. 引入恢复成本估算、草稿反馈与 async shutdown；将 runtime registry 注销纳入关闭协议。
5. 使用同一 benchmark 对比结果并执行完整 TUI/会话/MCP 测试；如出现语义回归，可分别关闭 delta 聚合、稳定 Markdown 缓存或索引路径并回退到原始渲染实现。
