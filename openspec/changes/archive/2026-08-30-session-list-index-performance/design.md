## Context

当前 JSONL 后端为每个会话维护可重建的元数据索引，列表操作逐个读取索引并按最近活动时间排序；只有索引缺失、损坏或源文件指纹变化时才回源构建。现有测试主要覆盖单会话命中和单个索引重建，没有证明会话数量增加后不会回退为全量正文扫描，也没有证明失效范围只限于受影响会话。

## Goals / Non-Goals

**Goals:**

- 用离线、可重复的扫描计数契约固定多会话列表的索引命中路径。
- 验证缺失、损坏和过期索引只触发对应会话回源，且其它有效会话继续可见。
- 验证 `continue_recent` 依据索引元数据选择最近目标，并把完整恢复检查限制在最终目标。
- 让文档和主规格明确“列表候选集不加载完整历史，单目标恢复可另行检查”的边界。

**Non-Goals:**

- 不引入跨进程常驻内存缓存、数据库或新的索引格式。
- 不以固定毫秒阈值作为验收标准，避免机器负载和文件系统差异造成脆弱测试。
- 不改变 JSONL 真相源、索引失效回退、列表排序或会话恢复语义。

## Decisions

### 1. 以回源次数而非耗时作为性能契约

在测试中统计索引构建/源文件扫描调用。相比硬编码耗时，调用次数能直接证明“有效索引不扫描正文”和“单个失效不扩散”，同时保持跨平台稳定。性能 benchmark 仍由既有非阻塞基线负责，不在本变更重复测量。

### 2. 覆盖多会话、单目标失效和最近选择三条路径

构造一组有有效索引的会话，列表/筛选时断言回源计数为零；再只改变一个源文件或索引，断言回源只命中该 id。对最近会话入口，先验证候选集合使用索引顺序，再允许最终选中会话执行其必要恢复检查。这样既覆盖 `SessionStore.list` 的直接用户路径，也覆盖 `SessionManager.continue_recent` 的组合路径。

### 3. 保持 fail-open 的单会话隔离

索引只是派生加速缓存。单个索引无法使用时，列表继续尝试该会话的 JSONL 回源；若回源也失败，则沿用现有隔离损坏文件的行为，跳过该目标而不阻断其它会话。测试只验证范围和结果，不要求自动修复原始 JSONL。

### 4. 以现有索引数据作为最近排序依据

不新增“最近会话专用索引”。`last_activity_at` 与稳定 id 已在会话索引中，列表排序和 `continue_recent` 复用同一结果，避免两个入口产生不同的最近会话定义。

## Risks / Trade-offs

- [Risk] 回源计数测试依赖内部索引构建 seam → Mitigation：只在契约测试中注入计数，不改变生产路径；断言用户可观察的列表结果和扫描范围。
- [Risk] 最终选中会话的恢复诊断仍可能扫描一次 JSONL → Mitigation：将其明确为单目标恢复成本，不把它与候选集合扫描混淆；列表本身保持索引命中。
- [Risk] 源文件同时被外部进程修改 → Mitigation：继续使用已有文件锁和源指纹校验，失效会话按现有回源/隔离语义处理。

## Migration Plan

无需数据迁移。先加入性能与失效隔离契约，再更新主规格和 v0.4 状态；回滚时可移除新增测试和文档，不影响 JSONL 或索引格式。
