## Context

See `proposal.md` for the motivation and user-visible scope. 当前 `Transcript` 已经把 RichLine 缓存限制在有限容量，并在首次布局后只物化视口附近的 block；但布局准备仍需扫描全部 block、重建行范围数组。`TuiRenderCoordinator` 已具备帧合并、协作式准备和 generation 校验，`Component.revision` 已具备内容缓存失效语义。设计必须保持这些边界、`TuiBackend` 接口和退出时的完整文档输出不变。

现有 TUI 是纯组件渲染层，不能依赖 Textual 才能计算布局。会话恢复已经对大历史使用后台构建；本变更只优化恢复完成后的 transcript 视口与交互，不改变 JSONL、会话消息或模型上下文。

## Goals / Non-Goals

**Goals:**

- 使长历史的可见范围定位和滚动准备不再每帧重建全量布局元数据。
- 只物化可见区及有限 overscan，并在 block 高度从估算值变为精确值时保持阅读锚点。
- 让 append、移除、内容 revision、工具展开/分页和 resize 只使受影响布局失效。
- 复用现有帧调度、协作式渲染和过期 generation 丢弃机制，保障输入、取消、滚动和确认的响应性。
- 保持当前视觉输出、事件顺序、点击命中、底部跟随和完整退出文档的可观察语义。
- 用固定规模 fixture 测量长会话的物化数量、渲染延迟、控制事件延迟和内存趋势。

**Non-Goals:**

- 不改变会话持久化格式、压缩策略、模型上下文或工具执行语义。
- 不引入 Textual 虚拟列表、数据库、第三方索引库或新的运行时依赖。
- 不把退出完整文档改为只输出当前视口；退出路径仍须生成全部内容。
- 不在本变更中重写 Markdown 语法或实现任意历史内容搜索；超长 Markdown 只沿用现有安全退化和渐进准备边界。
- 不要求后台恢复在 transcript 尚未构建完成时显示部分历史；恢复体验仍遵循既有 restoring 状态和过期结果保护。

## Decisions

### 1. 使用按宽度分片的增量布局索引

引入独立的 transcript 布局索引，保存每个 block 的稳定 token、revision、估算高度和已测量高度，并按终端宽度维护布局快照。快照由固定大小的 block chunk 和 chunk 级前缀和组成；块内最多扫描一个固定上限，chunk 之间使用前缀查找。

索引提供三类操作：

- 根据行号定位包含该行的 block，供视口选择和点击映射使用；
- 在 block 高度变化时按差值更新累计高度；
- 在尾部追加、移除或宽度切换时更新或重建受影响的 chunk。

这样可把普通滚动的布局元数据工作控制在 `O(log N + chunk_size)`，而不是每帧创建 `O(N)` 的 entries 列表。chunk 大小是内部实现参数，不暴露给用户。

**替代方案：**继续每帧重建列表实现最简单，但只减少了 RichLine 物化，不能解决长会话的线性布局成本；引入平衡树或第三方虚拟列表可以进一步降低复杂度，却会增加依赖和适配层，不符合当前纯 Python、纯组件边界。

### 2. 未物化 block 采用估算高度，进入视口后精确修正

没有当前宽度 RichLine 缓存的 block 不立即调用完整 `render`。索引先使用稳定的最小高度或可用的廉价内容元数据估算；视口选择后只渲染可见区及 overscan，并用实际行数修正对应记录。底部跟随时从尾部优先准备，避免估算误差导致最新内容不可见；非跟随状态下以当前锚点附近为优先。

高度修正可能改变总高度或 block 的绝对行号，因此每次修正都必须经过锚点恢复后再提交帧。若本帧仍有未稳定的可见 block，协作式准备可以在有限次数内继续修正；不能无限重试或提交包含空洞的视口。

### 3. 用 block 锚点替代仅保存绝对 scroll offset

用户离开底部后，Transcript 保存可见起点附近的 `block token + block 内行偏移`。工具展开/折叠、前方 block revision 更新和 resize 重新计算前缀行号后，恢复该锚点；锚点被删除时选择最近的前驱或后继 block。跟随底部时不保存阅读锚点，而是始终以最新总高度减去视口高度定位。

这可以保持现有 PageUp/PageDown 和滚轮语义，同时消除前方内容重排造成的跳屏。新 block 追加到用户已离开的底部时只增加新输出提示，不修改锚点。

**替代方案：**只调整绝对 `_scroll_top` 对尾部追加有效，但无法处理前方 block 展开和宽度变化；保存像素偏移也不适合当前按终端行工作的渲染模型。

### 4. revision 变化使用显式局部失效通知

布局索引不能为了发现 revision 变化而重新扫描全部 block。Transcript 持有 block 时注册轻量失效回调，`Component.touch()` 在 revision 增加后通知所属 transcript；移除 block 时解除注册。失效通知只标记一个 block 的当前宽度布局和高度记录，真正的 RichLine 计算仍延迟到该 block 进入可见窗口。

这保留现有 revision-aware cache 语义，并覆盖 assistant 增量、工具生命周期、分页游标和展开状态变化。未通过组件 mutation API 改变内容的调用方仍需显式触发既有 `touch()` 约定。

### 5. 保留 RichLine LRU，但增加布局元数据和总量边界

RichLine 缓存继续按 block token、宽度和 revision 复用，并保留现有宽度变体上限。布局索引只保存轻量高度和位置元数据；缓存淘汰同时考虑条目数和累计行/近似字节数，避免单个大 block 让缓存实际失控。缓存淘汰不得改变索引中的估算高度，也不得清除当前视口必须使用的结果而造成空行。

### 6. 工具结果分页按页访问，不在每次渲染时拆分完整正文

`OutputBuffer` 为结构化 metadata 优先提供总行数，并懒惰记录已访问页的起止偏移。展开或翻页只读取当前页所需的字符串范围；legacy 结果在缺少总行数时按需向后探测并缓存页边界。完整字符串仍保留在结果对象中，显式导出时直接输出原文。

这不会改变结果截断、artifact 引用或导出权限，只避免每次绘制可见工具页都重复构造完整 `lines` 列表。

### 7. 协作式渲染以“索引查询 + 可见物化”为最小工作单元

`render_progressive()` 先从索引得到可见区和 overscan 的候选 block，再逐个准备缺失布局；在固定批次后让出事件循环，并在每个批次边界检查最新 generation。宽度变化或内容更新产生新 generation 时，旧准备结果不得提交；如果旧任务已经完成准备，协调器仍通过现有 generation 检查丢弃旧帧。

同步快速路径继续保留给小会话。长会话不通过提高 yield 次数掩盖全量遍历，而是确保每帧准备本身不依赖完整历史。

### 8. 以纯组件等价性和 Textual 交互双层验收

新增离线测试验证新索引和旧的完整渲染基线逐行一致；新增 Textual `run_test()` 场景验证输入、Esc、PageUp/PageDown、确认和点击在长会话准备期间仍可到达。benchmark 增加 1,000、5,000、10,000 block，以及滚动、resize 和展开场景，记录可见物化数、索引更新数、帧 p50/p95、控制事件延迟、丢帧和峰值分配。

现有 Linux 基线和 CI 参数继续可比较，同时补充长会话参数；性能报告仍遵循当前非阻塞策略，先积累稳定数据再决定阈值。

## Risks / Trade-offs

- **估算高度不准导致初始位置短暂修正** → 只在提交前稳定当前视口，使用 block 锚点修正位置，并覆盖底部跟随和历史滚动回归。
- **组件 touch 回调造成生命周期泄漏或重复失效** → append/remove 成对注册和解除，测试重复 append、remove、clear 与对象回收路径，失效只增加一次 dirty 标记。
- **宽度切换使大量 block 同时过期** → 每个宽度独立维护快照，优先准备当前视口，限制宽度变体和 RichLine 缓存容量，过期 generation 不提交。
- **展开大工具结果仍可能因首次页边界探测产生延迟** → 每页访问设置有限扫描量并缓存页边界；结构化 metadata 优先，超大 legacy 结果保留明确的渐进或未知总量状态。
- **新索引与旧行映射不一致** → 保留完整渲染作为测试 oracle，针对空 block、分隔行、瞬态行、窄终端、滚动和展开建立等价性测试。
- **benchmark 机器差异导致阈值误报** → 固定 fixture、记录环境和参数，只比较相同平台/解释器/视口配置；性能 job 继续非阻塞。

## Migration Plan

1. 先加入索引、锚点、分页和统计的离线回归测试，并记录现有渲染输出作为 oracle。
2. 实现新布局路径，保留旧的完整 `all_rich`/`iter_lines` 退出路径和小会话同步路径。
3. 在长会话 fixture 与 Textual 集成测试中启用新路径，比较内容、点击映射、滚动和控制事件行为。
4. 更新 benchmark 文档及 V4-21 状态；若发现索引不变量破坏，回退到当前完整布局准备路径并保留诊断，不影响会话数据。
5. 通过全量测试、OpenSpec 校验、Ruff、构建和性能报告后再归档变更。
