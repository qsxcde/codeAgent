# context-budget Specification

## Purpose

为每次模型请求建立可解释且与具体 provider 无关的上下文预算契约，统一描述模型窗口、输入组成、输出预留、估算不确定性与实际用量，为后续请求前检查、压缩和诊断提供稳定事实来源。
## Requirements
### Requirement: 模型请求预算组成

系统 SHALL 为每次模型请求生成一个预算快照，快照 SHALL 至少包含有效模型上下文窗口、输出预留、输入预算、输入总估算值和可用余量，并分别标识 system prompt、工具定义、普通对话历史和工具结果的估算值。各组成项 SHALL 使用同一估算口径，预算快照 SHALL 不把会话累计用量当成本次请求输入预算。

#### Scenario: 预算包含完整请求组成

- **WHEN** Agent 准备向模型发送包含系统提示词、工具定义、对话历史和工具结果的请求
- **THEN** 预算快照分别报告这些组成项的估算值、输入总估算值、输出预留和有效窗口余量

#### Scenario: 输出预留占用窗口

- **WHEN** 计算一次模型请求的可用输入预算
- **THEN** 可用输入预算由上下文窗口扣除输出预留及明确声明的保留余量得到,不得把整个上下文窗口都当作可发送输入

#### Scenario: 空工具列表不产生工具定义估算

- **WHEN** 请求没有可用工具定义
- **THEN** 工具定义组成项为零,其它组成项仍按实际请求内容计算

### Requirement: 估算、实际用量与累计用量分离

系统 SHALL 将本地请求前估算、provider 返回的本轮实际 usage 和会话累计 usage 表示为三种互相独立的状态。一次请求收到实际 usage 后 SHALL 更新本轮实际状态,不得覆盖请求前估算;累计 usage SHALL 只聚合已经成功提交的会话轮次,不得由估算值推导或重复计入。

#### Scenario: 请求前只有估算

- **WHEN** 模型请求尚未收到 provider 响应
- **THEN** 预算状态标记为 estimate,调用方可以读取估算组成,但不得将其报告为 provider 实际用量

#### Scenario: 响应后保留两种数据

- **WHEN** provider 返回本轮 input、output 或缓存 token usage
- **THEN** 系统同时保留本轮请求估算与实际 usage,二者可分别用于预算诊断和用量展示

#### Scenario: 未提交轮次不进入累计

- **WHEN** 模型请求失败、取消或会话提交失败,即使 provider 返回了部分 usage
- **THEN** 该 usage 不进入会话累计值,但可以作为本轮失败诊断数据保留在运行期

### Requirement: 模型窗口元数据可追溯

模型目录和用户模型覆盖配置 SHALL 能读取正整数形式的 `context_window` 或 `contextWindow` 元数据,并将其绑定到最终模型选择结果。缺失、非法或无法确认来源的窗口值 SHALL 产生明确的 fallback 或 uncertain 标记,不得静默宣称该值为模型的精确能力上限。

#### Scenario: 目录记录提供窗口

- **WHEN** 模型目录记录包含有效的上下文窗口字段
- **THEN** 最终模型规格携带该窗口值,预算快照使用该值作为有效模型窗口

#### Scenario: 用户覆盖保留窗口

- **WHEN** 用户通过模型覆盖配置声明模型及其上下文窗口
- **THEN** 解析后的模型规格保留该窗口元数据,模型切换后新请求使用覆盖后的值

#### Scenario: 窗口元数据缺失

- **WHEN** 模型目录没有有效上下文窗口元数据
- **THEN** 系统使用已定义的保守兜底或不确定状态继续生成预算,并向诊断层暴露来源与不确定性

#### Scenario: 恢复压缩上下文后切换模型

- **WHEN** 进程重启后恢复包含摘要和保留窗口的会话,随后切换到窗口或输出限制不同的模型
- **THEN** 下一次预算只按摘要、保留消息和新模型请求组成重新计算，物理已压缩消息、旧模型预算和累计 usage 不进入本次输入估算

### Requirement: 预算快照不改变持久化上下文

系统 SHALL 为预算计算和预算感知的上下文准备生成当前请求使用的临时视图或诊断快照，不得删除、重排或改写会话持久化历史。调用方 SHALL 能在不改变原始消息列表的情况下重新计算同一请求的预算；上下文扩展的失败或超时也不得产生部分持久化修改。

#### Scenario: 预算计算保持历史不变

- **WHEN** 系统为一次请求计算预算或执行预算感知的上下文准备
- **THEN** 会话原始消息、父级关系和压缩记录保持不变，只有本次模型请求使用的临时视图可以变化

#### Scenario: 重复计算可观察一致

- **WHEN** 请求组成和模型窗口没有变化且重复计算预算
- **THEN** 预算组成、估算口径和来源标记保持一致，不会因读取或诊断动作累积额外 token

#### Scenario: 扩展失败保持历史可重试

- **WHEN** 上下文扩展抛出异常、返回非法结果或超时
- **THEN** 本次模型请求失败但原始历史仍可用于下一次请求，且不会残留扩展生成的临时消息

### Requirement: 上下文扩展隔离与兼容组合

系统 SHALL 为每次模型请求创建独立的临时消息视图，并先调用旧式 `transform_context`，再调用预算感知的上下文准备扩展；配置了两类扩展时不得绕过任一入口。两类扩展的输入 SHALL 只包含当前请求范围内的消息副本，预算感知扩展 SHALL 只接收中立的消息、工具定义和预算快照。扩展返回值 SHALL 是消息集合且其中每项均为有效消息；非法返回值、扩展异常或超时 SHALL 以结构化上下文准备错误结束当前模型请求，不得静默回退到未变换上下文。转换结果只作用于当前模型请求，不得修改会话持久化历史或组合根中的工具对象。

#### Scenario: 旧扩展与预算扩展按顺序组合

- **WHEN** AgentLoopConfig 同时配置 `transform_context` 和 `context_preparer`
- **THEN** 系统先把旧转换器的结果交给预算扩展，再把预算扩展返回的临时消息交给模型，原始会话消息保持不变

#### Scenario: 扩展只看当前请求的隔离视图

- **WHEN** 上下文扩展读取或修改消息、工具定义或嵌套参数 schema
- **THEN** 扩展只能观察和修改当前请求的副本，持久化历史、真实工具实例及其 schema 保持不变

#### Scenario: 预算扩展接收中立工具视图

- **WHEN** 请求包含内置工具、MCP 工具或其它工具适配器
- **THEN** `ContextPreparationRequest.tools` 只包含名称、描述和参数 schema 等中立定义，扩展不能获得或修改实际工具实例

#### Scenario: 扩展返回非法消息集合

- **WHEN** 任一上下文扩展返回 `None`、不可迭代值或包含非 Message 项的集合
- **THEN** Runtime 发出 `context_preparation_failed` 错误并阻断模型调用，不使用原始上下文作为隐式回退

#### Scenario: 扩展调用超时

- **WHEN** 配置了正的上下文扩展超时且任一扩展在该时限内未完成
- **THEN** Runtime 发出错误码为 `context_transform_timeout` 的上下文准备错误并阻断模型调用；已持久化历史保持不变

#### Scenario: 取消上下文扩展

- **WHEN** Agent 在等待上下文扩展时被取消
- **THEN** 取消异常继续向调用方传播，不被转换成普通准备失败，且不得启动模型请求

### Requirement: 不确定窗口策略显式可见

当模型适配器无法提供精确上下文窗口时,系统 SHALL 生成状态为 `uncertain` 的预算快照，并根据显式的 `uncertain_budget_policy` 决定是否进入预算扩展。默认 `allow` SHALL 保持旧适配器可用；`fail` SHALL 在调用扩展或模型前以结构化上下文准备错误结束。

#### Scenario: 不确定窗口允许兼容运行

- **WHEN** 模型没有预算描述能力且策略为 `allow`
- **THEN** 系统发布带 `fallback` 来源的 `uncertain` 快照并继续请求,不得将其标记为精确估算

#### Scenario: 不确定窗口阻断请求

- **WHEN** 模型没有预算描述能力且策略为 `fail`
- **THEN** 系统先发布 `uncertain` 快照,随后返回 `context_preparation_failed`,不调用预算扩展和模型

### Requirement: 自动压缩使用下一次请求预算

自动压缩策略 SHALL 使用代表下一次模型请求的预算快照作为决策输入。该快照 SHALL 基于当前已提交历史、当前摘要、可用工具定义、system prompt、输出预留、安全余量和最终模型窗口重新计算,并分别暴露输入估算、有效输入预算、余量、窗口来源和不确定性。该决策不得依赖会话累计 usage,也不得要求 provider 必须返回本轮实际 input tokens。

#### Scenario: 工具结果影响下一次压缩判断

- **WHEN** 一轮对话产生较大的工具结果并成功提交,系统准备下一次模型请求
- **THEN** 下一次请求预算包含该工具结果的估算,自动压缩策略使用更新后的预算判断,不复用上一模型请求的预算结果

#### Scenario: 缺少实际 usage 时使用本地估算

- **WHEN** provider 没有返回本轮实际 input tokens,但模型窗口和请求组成可用于本地估算
- **THEN** 系统仍生成下一次请求的预算快照并供自动压缩消费,同时保留 estimate 或 uncertain 来源标记

#### Scenario: 模型切换重新计算压缩预算

- **WHEN** 会话切换到上下文窗口或输出限制不同的模型
- **THEN** 下一次请求和自动压缩分别使用新模型元数据重新计算有效输入预算、触发阈值和压缩目标,不得沿用旧模型的预算边界

#### Scenario: 压缩后重新验证预算

- **WHEN** 自动压缩生成摘要和保留消息候选
- **THEN** 系统用同一预算口径重新估算该候选作为下一次请求的输入,并将压缩前后预算与判定结果提供给诊断层

#### Scenario: 恢复后按逻辑上下文判断

- **WHEN** 进程重启后恢复包含最新摘要和保留窗口的会话
- **THEN** 自动压缩判断只使用该逻辑上下文和当前模型请求组成，不因 JSONL 中物理保留的已压缩消息而重复触发或错误增加输入估算

### Requirement: 工具结果按请求预算治理

系统 SHALL 在工具结果进入下一次模型请求前,依据该请求的有效输入预算、输出预留、安全余量、已有历史、system prompt 和工具定义计算工具结果可用空间。结果治理 SHALL 可进一步裁剪或生成确定性摘要,并保留原始总量、当前展示量和治理原因;不得用会话累计 usage 或上一请求的预算代替当前判断。

#### Scenario: 剩余预算不足时缩小结果

- **WHEN** 工具结果加入后下一次请求的有效输入空间不足以容纳完整结果
- **THEN** 系统按工具策略缩小模型可见文本或返回结构化跳过/摘要结果,请求不得因为无界工具文本直接越过预算边界

#### Scenario: 工具结果预算随模型切换变化

- **WHEN** 会话切换到上下文窗口或输出限制不同的模型
- **THEN** 下一次工具结果治理使用新模型预算重新计算,不得沿用旧模型的结果上限或保留比例

#### Scenario: 多个结果互不污染

- **WHEN** 同一模型回合产生多个工具结果
- **THEN** 每个结果按自身内容、工具策略和共享剩余预算治理,一个结果的截断或失败不得覆盖其它 tool_call_id 的状态和元数据

#### Scenario: 缺少 provider usage 仍可治理

- **WHEN** provider 未返回本轮实际 input tokens
- **THEN** 系统使用本地请求组成估算及其 estimate/uncertain 标记执行结果治理,不得因缺少实际 usage 关闭限制或宣称精确预算

#### Scenario: 关键事实不因裁剪丢失

- **WHEN** 工具正文因硬上限或请求预算被裁剪
- **THEN** 路径、退出码、错误、变更摘要、继续读取参数和完整性状态等结构化事实仍可供模型、事件和展示层消费
